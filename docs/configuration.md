# Настройка

Все настройки бота - в `src/app/config.py` и `.env`. Идея проекта: менять поведение можно без правки кода.

## Режим строгих ID (по умолчанию)

Бот работает строго по ID: поиск существующих объектов по имени **отключён**. Имена в Discord не уникальны — одноимённая роль не должна получить доступ к приватным тикетам и логам, а `is_staff()` — право на решения по заявкам и снятие AFK.

- Заданный, но не найденный ID (удалили объект, опечатались, не тот тип канала) — фатальная ошибка: бот после подключения выводит список проблем по каждому серверу и останавливается, до обработки первой заявки. Мусор вроде `ROLE_ADMIN_ID=abc` отсекается ещё раньше, при проверке конфига.
- Незаполненный ID — не фатально: роль просто не участвует в доступах (deny by default), категория тикетов и лог-центр бот создаёт приватными сам и запоминает их ID, кнопка обзвона честно сообщает, что канал не найден.
- `ALLOW_NAME_FALLBACK=true` — явный opt-in legacy-режима для локальной разработки: поиск по имени снова работает, а проверки превращаются в предупреждения. Режим специально помечен небезопасным и не должен попадать в production-конфигурации.

Пути до базы (`DB_PATH`) и до логов (`LOG_DIR`) считаются от папки `src/app` и переопределять их сейчас нельзя - только правкой `config.py`.

## Лог-центр

Один приватный канал для всей отчётности бота. Внутри - 7 веток: `📝-заявки` (новые заявки), `⚖️-решения` (принял/отклонил, кто и почему), `🔴-afk` (входы, выходы, истёкшие), `🔊-обзвоны` (кто кого вызвал и куда), `📊-статистика`, `🚨-ошибки`, `🧾-аудит` (удаление персональных данных, ретенция).

Два режима, чётко разделённых:

- **Управляемый ботом** (`LOG_CHANNEL_ID` пуст): бот сам создаёт приватный канал и ветки (закрыто для `@everyone`, открыто боту и `STAFF_ROLE_IDS`) и запоминает их ID в БД. Права такого канала принадлежат боту: если их кто-то ослабил, бот принудительно возвращает приватные и пишет предупреждение в лог.
- **Подключение к существующему** (задан `LOG_CHANNEL_ID`, опционально `LOG_THREAD_*_ID`): каждый объект проверяется при старте и на каждой отправке — текстовый канал/ветка этого сервера, ветка принадлежит настроенному каналу, `@everyone` без просмотра, доступ ограничен ботом и стафф-ролями. ID веток без `LOG_CHANNEL_ID` — ошибка конфигурации.

Принцип fail closed: транскрипты не отправляются в канал, не прошедший проверку приватности — никакого fallback в корень канала или «похожий по имени» канал. Отказ пишется в лог-файл бота (CRITICAL/ERROR) и виден оператору сразу; в production бот не стартует с небезопасной настройкой лог-центра. Архивированную ветку бот пытается разархивировать, ошибки логирования не роняют основную логику (send_to_log просто вернёт None).

Роли с правом Administrator видят любой канал на уровне Discord — это граница доверия сервера, проверка приватности её не охватывает.

### Поля форм RP_FIELDS и CAPT_FIELDS

Каждое поле - кортеж из четырёх значений:

```python
("Никнейм в игре + статик", "Ваш игровой ник и статик (если есть)", True, 100)
#  ^label                     ^placeholder                             ^required ^max_length
```

Жёсткие лимиты Discord, выход за которые сломает форму:

- полей в форме — максимум **5**
- `label` — максимум **45** символов
- `placeholder` - максимум **100** символов
- `max_length` - от 1 до 4000

Поля с `max_length` больше 150 вводаются многострочным полем, остальные - однострочным.

### Настройки AFK

| Переменная | Значение | Описание |
|------------|----------|----------|
| `AFK_COOLDOWN_SECONDS` | `30` | Кулдаун автоответа на упоминание для пары «кто упомянул - кто в AFK» |
| `AFK_NICK_PREFIX` | `[AFK] ` | Префикс ника у AFK-пользователя |

Все тексты AFK тоже в конфиге, группа `AFK_*`:

| Группа | Переменные |
|--------|-----------|
| Заголовки | `AFK_EMBED_TITLE`, `AFK_EMBED_DESCRIPTION`, `AFK_MENU_TITLE`, `AFK_MENU_NO_AFK`, `AFK_MENU_TOTAL` |
| Модальное окно взятия | `AFK_MODAL_TITLE`, `AFK_MODAL_REASON_LABEL`, `AFK_MODAL_REASON_PLACEHOLDER`, `AFK_MODAL_DURATION_LABEL`, `AFK_MODAL_DURATION_PLACEHOLDER` |
| Окно возврата | `AFK_RETURN_MODAL_TITLE`, `AFK_RETURN_CONFIRM`, `AFK_RETURN_DURATION_LABEL` |
| Кнопки | `AFK_BUTTON_LEAVE`, `AFK_BUTTON_RETURN`, `AFK_BUTTON_REFRESH`, `AFK_BUTTON_STAY` |
| Сообщения | `AFK_RETURN_SUCCESS`, `AFK_RETURN_STAY`, `AFK_RETURN_ERROR`, `AFK_NOT_AFK`, `AFK_INVALID_USER`, `AFK_REASON_DEFAULT` |
| Статус и проверка | `AFK_AFK_STATUS`, `AFK_CHECKED_NOT_AFK` |
| Статистика | `AFK_STATS_TITLE`, `AFK_STATS_NO_DATA`, `AFK_STATS_TOTAL`, `AFK_STATS_TOTAL_TIME`, `AFK_STATS_LONGEST` |
| Автоответ | `AFK_AUTO_REPLY` - шаблон с `{mention}`, `{reason}`, `{duration}` |
| Возврат через голос | `AFK_VOICE_RETURN_TITLE` (шаблон с `{user}`), `AFK_VOICE_RETURN_DESC` |

## Примеры правок

Сменить префикс команд:

```python
CMD_PREFIX = "."
```

Сменить кулдаун автоответа на минуту:

```python
AFK_COOLDOWN_SECONDS = 60
```

Добавить поле в CAPT-форму (помним: максимум 5 полей, label до 45 символов):

```python
CAPT_FIELDS = [
    ...("Опыт в каптах", "Сколько заходов сыграли", False, 100),
]
```

## Когда бот подхватывает изменения

Только при перезапуске. Конфиг читается один раз при импорте модулей.
