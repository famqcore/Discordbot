# Установка и запуск

Инструкция с нуля до работающего бота. Если всё под рукой, уложитесь минут в пятнадцать.

## 1. Что нужно

- Python 3.11 (именно на нём собраны lock-файлы с хешами; для Docker-варианта Python на хосте не нужен).
- Права администратора на Discord-сервере.
- Приложение бота в [Discord Developer Portal](https://discord.com/developers/applications).

## 2. Код и зависимости

```bash
git clone https://github.com/famqcore/famqcore_discord.git
cd famqcore_discord/src/app
python -m pip install --require-hashes -r requirements.txt
```

Флаг `--require-hashes` обязателен: в `requirements.txt` зафиксированы версии и SHA-256 всех пакетов.

## 3. Токен

```bash
cp .env.example .env
```

Откройте `.env` и впишите токен:

```env
TOKEN=ваш_токен
```

Токен берётся в Developer Portal: Applications, ваш бот, вкладка Bot, Reset Token, Copy. Никому его не показывайте, файл `.env` в Git не попадает (он в `.gitignore`).

## 4. Привилегированные интенты

В Developer Portal, вкладка Bot, раздел Privileged Gateway Intents:

- MESSAGE CONTENT INTENT - без него бот не видит текст сообщений и команды с `!` не работают;
- SERVER MEMBERS INTENT - без него бот не видит участников сервера.

## 5. Приглашение на сервер

Developer Portal, OAuth2, URL Generator:

- scope: `bot`;
- права: View Channels, Send Messages, Embed Links, Attach Files, Read Message History, Manage Messages, Manage Channels, Manage Roles, Manage Nicknames, Create Public Threads, Send Messages in Threads.

Зачем именно эти: каналы и категории бот создаёт сам, ветки лог-центра - это треды внутри приватного канала, транскрипт тикета отправляется файлом, а префикс `[AFK] ` меняет ник участника. Права Administrator боту не нужны, к голосовым каналам он не подключается.

Откройте полученную ссылку и выберите сервер.

Важно: роль бота в списке ролей сервера должна стоять **выше** ролей, которые он выдаёт и выше участников, которым меняет ник. Иначе выдача роли «Подал заявку» и префикс `[AFK]` просто не сработают.

## 6. Настройка ID ролей и каналов

По умолчанию бот работает строго по ID из `.env`, поиск по имени выключен (почему - в [configuration.md](configuration.md)). Включите в Discord режим разработчика (Настройки, Расширенные), дальше правый клик по роли или каналу и «Копировать ID».

Роли:

- `ROLE_APPLIED_ID` - роль, которую бот выдаёт при подаче заявки;
- `ROLE_RECRUITER_ID` - рекрутёр: доступ к тикетам, пинг в новых заявках, модерация AFK;
- по желанию `ROLE_OWNER_ID`, `ROLE_DEP_OWNER_ID`, `ROLE_ADMIN_ID`, `ROLE_SUPPORT_ID` - дополнительный доступ к тикетам и логам.

Каналы:

- `TICKETS_CATEGORY_ID` - категория для тикетов. Не зададите - бот создаст свою при первой заявке;
- `VOICE_CHANNEL_IDS` - до трёх голосовых каналов обзвона через запятую, в том же порядке, что подписи кнопок в `VOICE_CHANNELS`;
- `LOG_CHANNEL_ID` - существующий приватный лог-канал со старой схемой «ветки внутри канала». Можно оставить пустым, так и задумано: тогда бот сам создаст приватную категорию `logs bot` и в ней отдельные каналы `📝-заявки`, `⚖️-решения`, `🔴-afk`, `🔊-обзвоны`, `📊-статистика`, `🚨-ошибки`, `🧾-аудит`, а их ID запомнит в своей базе.

Если `LOG_CHANNEL_ID` задан, канал обязан быть приватным: `@everyone` без права просмотра, доступ только у бота и стафф-ролей. Иначе бот откажется туда писать и не запустится. ID веток (`LOG_THREAD_*_ID`) задаются только вместе с `LOG_CHANNEL_ID`.

После подключения бот один раз проверяет все заданные ID на каждом сервере. Любой заданный, но не найденный объект (удалили, опечатались, канал не того типа) останавливает бота: в лог выводится список проблем, процесс завершается с кодом 1. Исправьте `.env` и запустите снова.

Для локальной разработки без реальной инфраструктуры есть небезопасный режим `ALLOW_NAME_FALLBACK=true`: поиск по именам из `config.py` снова работает, а проверки становятся предупреждениями. Вместе с ним нужно поставить `ENVIRONMENT=development`, иначе валидация конфига не пропустит запуск.

Один процесс бота спокойно обслуживает несколько серверов: тикеты, статистика и AFK пишутся вместе с `guild_id`. Старые записи без сервера миграция переносит в служебный `guild_id = 0`.

## 7. Запуск

```bash
cd src/app
python main.py
```

Перед подключением бот проверяет конфигурацию и наличие токена, потом создаёт или мигрирует базу. В консоли появится что-то вроде:

```
bot.startup outcome=schema_ready version=v4
bot.ready outcome=ok user=FAMQCORE Bot#0000 guilds=1
```

Тесты внутри рабочего процесса не запускаются. Прогоняйте их отдельно перед первым стартом и перед обновлением:

```bash
TOKEN=dummy PYTHONWARNINGS=error python -m unittest discover -s tests -t . -v
```

## 8. Проверка

1. Напишите в любом канале `!famqcore` - бот ответит панелью с кнопками «RP ЗАЯВКА» и «CAPT ЗАЯВКА».
2. Подайте тестовую заявку - должен появиться приватный канал вида `rp-ваш-ник`.
3. Напишите `!afk` - появится меню AFK из трёх кнопок.

## Где логи

- Консоль: цветной вывод.
- Файл `src/app/logs/bot.log`: ротация, 3 архива по 5 МБ.

## Частые проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| Бот молчит на команды | Не включён MESSAGE CONTENT INTENT | Пункт 4 |
| Не выдаёт роль, не меняет ник | Роль бота ниже нужной роли или участника | Поднять роль бота выше в настройках сервера |
| Не стартует, в логе CRITICAL про ID | Заданный ID не найден на сервере | Исправить или очистить ID в `.env` и перезапустить |
| Пишет, что роль не найдена | ID роли не задан, а поиска по имени нет | Вписать нужный `ROLE_*_ID` в `.env` |
| Падает из-за TOKEN | Токен не задан или неверный | Проверить `.env` |
| Отказывается писать в лог-канал | Канал из `LOG_CHANNEL_ID` не приватный | Закрыть канал для `@everyone`, оставить доступ боту и стафф-ролям |
| `GUILD_TIMEZONE: пояс «Europe/Moscow» не найден` | В системе нет базы часовых поясов IANA, типично для Windows | `pip install tzdata` и перезапустить. В свежих зависимостях пакет уже есть, помогает `pip install -r requirements.txt` заново |
| Кнопки не реагируют после рестарта | Запущена старая версия или поменяли `custom_id` | Обновить код и посмотреть лог `setup_hook` |

Запуск через Docker описан в [deployment.md](deployment.md).
