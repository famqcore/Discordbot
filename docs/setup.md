# Установка и запуск

Пошаговая инструкция от нуля до работающего бота. Занимает минут пятнадцать.

## 1. Требования

- Python 3.10 или новее (для Docker-варианта только Docker)
- Discord-аккаунт с правами администратора на вашем сервере
- Зарегистрированное приложение бота в [Discord Developer Portal](https://discord.com/developers/applications)

## 2. Клонирование и зависимости

```bash
git clone https://github.com/famqcore/Discordbot.git
cd Discordbot/src/app
pip install -r requirements.txt
```

## 3. Токен

Скопируйте пример окружения и впишите токен:

```bash
cp .env.example .env
```

Файл `.env` откройте и заполните:

```env
TOKEN=ваш_токен
```

Токен берётся в Developer Portal: Applications - ваш бот - Bot - Reset Token - Copy. Никому его не показывайте, файл `.env` в гит не попадает (он в `.gitignore`).

## 4. Привилегированные интенты

Без них бот не сможет читать сообщения и видеть участников. В Developer Portal: Bot - Privileged Gateway Intents, включите:

- MESSAGE CONTENT INTENT - без него не работают команды с префиксом `!`
- SERVER MEMBERS INTENT - без него бот не видит участников сервера

## 5. Приглашение бота на сервер

В Developer Portal: OAuth2 - URL Generator:

- scope: `bot`
- права: Manage Roles, Manage Channels, Send Messages, Embed Links, Manage Messages, Read Message History, View Channels

Выдавайте только перечисленные права: бот не подключается к голосовым каналам и не требует Administrator.

Откройте полученную ссылку и выберите сервер.

Важно: роль бота в настройках сервера должна стоять **выше** ролей, которые он выдаёт (например «Подал заявку»), иначе выдача ролей молча не сработает.

## 6. Настройка сервера под конфиг

По умолчанию бот ищет объекты по именам. Создайте на сервере (или поменяйте имена в `config.py`, см. [configuration.md](configuration.md)):

Категория для тикетов:

- `FAMQCORE • заявки` (TICKETS_CATEGORY_NAME)

Роли:

- `Подал заявку` (ROLE_APPLIED) - выдаётся при подаче заявки
- `𝐑𝐞𝐜𝐫𝐮𝐢𝐭👨🏻‍💻` (ROLE_RECRUITER)
- `𝙊𝙬𝙣𝙚𝙧👑` (ROLE_OWNER)
- `𝘿𝙚𝙥.O𝙬𝙣𝙚𝙧⭐` (ROLE_DEP_OWNER)
- `Admin` (ROLE_ADMIN)
- `Support` (ROLE_SUPPORT)

Каналы:

- `📋ᥙᴛ᧐ᴦᥙ-ɜᥲяʙ᧐κ` (LOG_CHANNEL_NAME) - лог-центр. Если его нет, бот создаст приватный канал и тематические ветки автоматически
- `🔊Обзвон 1`, `🔊Обзвон 2`, `🔊Обзвон 3` (VOICE_CHANNELS) - голосовые для обзвона

Категорию для тикетов тоже можно не создавать руками - бот заведёт её при первой заявке.

> Один экземпляр бота может обслуживать несколько Discord-серверов: тикеты, статистика и AFK-данные пишутся с `guild_id`. Старые записи без сервера мигрируются в служебный `guild_id = 0`.

## 7. Запуск

```bash
cd src/app
python main.py
```

Перед подключением бот проверяет конфигурацию и наличие токена. При успешном старте в консоли появится сообщение:

```
Бот FAMQCORE Bot#0000 запущен
```

Автотесты не запускаются внутри production-процесса. Перед первым стартом и перед обновлением выполните их отдельно:

```bash
TOKEN=dummy python -m unittest discover -s tests -v
```

## 8. Проверка

1. Напишите в любом канале `!famqcore` - бот ответит панелью с кнопками RP и CAPT.
2. Подайте тестовую заявку - должен появиться приватный канал.
3. Напишите `!afk` - появится меню AFK.

## Где логи

- Консоль - цветной вывод
- Файл `src/app/logs/bot.log` - с ротацией, хранятся 3 архива по 5 МБ

## Частые проблемы

| Симптом | Причина | Что делать |
|---------|---------|-----------|
| Бот молчит на команды | Не включён MESSAGE CONTENT INTENT | Пункт 4 |
| Не выдаёт роль | Роль бота ниже выдаваемой | Поднять роль бота выше в списке ролей |
| Не находит роль/канал | Неверный ID или имя fallback не совпадает | Проверить `.env` и `config.py` |
| Падает, пишет про TOKEN | Токен не задан или неверный | Проверить `.env` |
| Кнопки не реагируют после рестарта | Запущена старая версия или изменены `custom_id` | Обновить код и проверить лог `setup_hook` |

Для запуска через Docker смотрите [deployment.md](deployment.md).
