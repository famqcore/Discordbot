# Дорожная карта

Проект находится в beta. Актуальный технический план и критерии первого безопасного релиза собраны в [epic #108](https://github.com/yyangdev/majestick-famq-discord-bot/issues/108). Детальные задачи остаются в [GitHub Issues](https://github.com/yyangdev/majestick-famq-discord-bot/issues).

Порядок важен: сначала безопасность данных и стабильность, затем крупные продуктовые функции.

## v0.2.0 — Security & data isolation

Цель: один экземпляр бота может безопасно работать с несколькими Discord-серверами.

1. Поддерживать зелёный CI; запрет merge без required check остаётся настройкой GitHub branch protection (#104).
2. Миграции схемы БД через `PRAGMA user_version` (#91).
3. Изоляция тикетов, статистики и AFK-данных по `guild_id` (#26, #80).
4. Cooldown на команды/кнопки и ограничение одного открытого тикета на пользователя (#93).
5. Политика доступа, хранения и удаления данных заявок (#105).
6. Добавить security baseline: `SECURITY.md`, аудит зависимостей, SAST и проверку секретов (#96, #107).

## v0.3.0 — Reliability & releases

Цель: воспроизводимый деплой, наблюдаемость и восстановление после сбоя.

1. Перевести контейнер на непривилегированного пользователя и добавить healthcheck (#45).
2. Добавить graceful shutdown и обработку ошибок фоновых задач (#68, #94).
3. Настроить backup/restore базы и политику ретенции (#98).
4. Включить coverage threshold и постепенную типизацию (#89, #90).
5. Ввести CHANGELOG, semver, GitHub Releases и публикацию Docker-образа (#95).
6. Синхронизировать документацию и добавить скриншоты пользовательских сценариев (#106).

## После стабилизации

### Web-панель

- настройка текстов и цветов embed;
- управление ролями, каналами и правами по ID;
- просмотр статистики и истории в пределах одного сервера;
- авторизация через Discord OAuth2 и строгая проверка guild permissions.

### Система мероприятий

- регистрация основного и резервного состава;
- уведомления участников;
- архив материалов мероприятия;
- система тиров и запросов на повышение тира.

### Внутренняя экономика и отчёты

- отчёты участников;
- начисление виртуальных монет;
- магазин и розыгрыши;
- аудит действий high-состава.

Эти функции не должны добавляться раньше изоляции данных, миграций и резервного копирования.
