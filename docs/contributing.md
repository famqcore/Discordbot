# Как помочь проекту

Пригодятся руки разработчиков, тестировщиков и тех, кто умеет понятно писать. Даже поправленная формулировка в интерфейсе делает жизнь модераторов проще.

## С чего начать

- **Пишете на Python:** возьмите задачу в [Issues](https://github.com/famqcore/famqcore_discord/issues) или предложите свою.
- **Хотите тестировать:** поднимите бота на тестовом сервере, пройдите сценарии из [commands.md](commands.md) и заведите баг с шагами воспроизведения.
- **Работаете с текстом:** улучшайте формулировки в документации и в `config.py` через Issue или сразу Pull Request.

## Процесс

1. Найдите или заведите [Issue](https://github.com/famqcore/famqcore_discord/issues) и напишите, что берёте задачу.
2. Создайте ветку `feature/что-делаете` или `fix/номер-issue`.
3. Сделайте минимальное изменение, которое решает задачу. Тексты и параметры кладите в `config.py`.
4. Добавьте тесты на новое поведение.
5. Перед PR прогоните проверки:
   ```bash
   python -m pip install --require-hashes -r src/app/requirements-dev.txt
   cd src/app
   TOKEN=dummy PYTHONWARNINGS=error python -m unittest discover -s tests -t . -v
   ruff check .
   ruff format --check .
   ```
   Полный сценарий с coverage описан в [testing.md](testing.md).
6. Откройте PR: что изменилось, зачем, как проверяли, какой Issue закрывает.

## Стиль кода

- PEP 8 и форматирование Ruff.
- Маленькие функции и сфокусированные изменения.
- Комментарий объясняет причину решения, а не пересказывает код.
- Не коммитьте токены, персональные данные, `.env`, базы SQLite и логи.

Короткая памятка для тех, кто пришёл сразу в PR: [CONTRIBUTING.md](../CONTRIBUTING.md).
